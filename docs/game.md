# 实验、游戏、游戏框架：同一个内核的三种形态

`questions.md` 是把这个系统当实验来看的。本文换两个角度：把它当游戏，以及把它当游戏框架。

---

## 1. 三种形态共用一个内核

内核就是前面几份文档定下来的东西：一个自己涌现的世界，一个观测层，一串有立场的 LLM 中介，一套受约束的干预杠杆，以及永不清零的历史。

同一个内核，优化目标不同，就是三种不同的东西：

| | 实验 | 游戏 | 游戏框架 |
| --- | --- | --- | --- |
| 优化什么 | 真相和因果 | 玩家的体验和意义 | 让别人能快速做出这类游戏 |
| 人是什么 | 被试 | 玩家 | 开发者，然后才是玩家 |
| 中介 | 必须诚实、可审计 | 可以有个性、有偏见，但偏见要是可被发现的机制 | 一个可配置的运行时 |
| 分叉 | 对照工具，越多越好 | 稀缺能力，或者干脆不给 | 基础设施 |
| 时间 | 越快越好 | 匹配人的生活节奏 | 由上层游戏决定 |
| 失败 | 一个数据点 | 要有意义，悲剧也要好看 | 要能被上层游戏捕捉和呈现 |
| 成功标准 | 可证伪的结论 | 留存、口碑、玩家自己讲出来的故事 | 有第二个、第三个游戏用它做出来 |

它们并不冲突，但必须选一个作为主形态，否则每个决定都会左右摇摆。

## 2. 当游戏：会变成什么

### 2.1 核心设定：你只能通过使者接触这个世界

> 你是一个远方的存在。你看不到河谷，只能收到住在那里的使者寄来的信。使者有自己的性格和立场，会误解，会偏心，偶尔会瞒着你。你能做的，是给使者指示、在有限的次数内施加“神迹”，并且一点点学会河谷居民的语言。世界在你离线时继续运行，你上次的决定造成的后果，会一直留在那里。

这个设定几乎是把框架原样搬了过来：

| 框架里的东西 | 游戏里是什么 |
| --- | --- |
| 总中介 | 你的书记官或顾问，负责整理信件、写编年史 |
| 使者 | 驻在河谷不同地方的角色，每人有性格、立场和记忆 |
| 接应者 | 居民里慢慢出现的“翻译”或“祭司”，你可能会和其中一些建立长期关系 |
| 干预预算 | 神迹次数，或者你在居民中积累的“信任” |
| 历史不清零 | 永久世界，没有读档 |
| 分叉 | 稀有的“预言”：花很大代价，看一眼另一种可能 |

### 2.2 进度靠“理解”，而不是数值

大多数游戏的成长来自等级和装备。这里的成长可以来自**你对这个世界理解得有多深**，正好对应框架里因果干预的四个层级：

1. **只能看**：通过使者的信件和编年史了解发生了什么。
2. **会借力**：知道居民会利用哪些结构（浅滩、堤、记号），能通过使者引导它们去用。
3. **能读懂**：破译了一部分居民的信号，可以直接“听懂”它们，不再完全依赖使者的转述。
4. **能改写**：理解了局部物理，可以用神迹精确地改变某处的地形和水流。

所以玩家越理解世界，影响力就越精确。游戏奖励的是理解，而不是刷数值。

### 2.3 破译是整个游戏里最独特的部分

居民的信号系统是从零涌现的，每个世界、每个玩家遇到的都不一样，没有设计师写好的答案。这在 Chants of Sennaar、Heaven's Vault 这类破译游戏里是做不到的：它们的语言是手写的，破译完就结束了。

玩家的“破译笔记”就是游戏界面：

- 记录听到的信号和当时的情境；
- 提出猜测，比如“这个符号是不是‘上游有食物’的意思”；
- 通过使者去**实际发出这个信号**，看居民怎么反应；
- 世界的反应就是判卷人，不需要任何人预先写好正确答案。

LLM 可以当助手，但不能直接给出答案，否则破译的乐趣就没了。

### 2.4 研究问题变成可以亲身感受的机制

`questions.md` 里那些问题，在游戏里不再是测出来的指标，而是玩家会亲身撞上的东西：

| 研究问题 | 在游戏里的体验 |
| --- | --- |
| 中介报道真相还是戏剧 | 你的某位使者总爱夸大冲突。你发现以后，是换掉他，还是继续享受精彩的信？ |
| 委托链越长，人还能否掌舵 | 你的一道指示层层传下去，最后变成了别的样子。你可以一层层往下追，看是在哪里走了样 |
| 陌生语言能否被翻译和监督 | 破译玩法本身；居民可能发展出只在同伴之间用、瞒着使者的信号 |
| 中介会不会把文化压平 | 你的使者和居民接触越多，当地方言就越像使者的说法。你得到了方便，却失去了一种语言 |
| 公地会不会被吃光 | 你帮上游修了堤，下游旱了。这件事会一直留在编年史里 |

这类游戏的意义在于：玩家不是被告知“AI 中介会扭曲信息”，而是自己被扭曲过一次，然后学会分辨。

### 2.5 节奏：异步，把“慢”变成特点

涌现很慢，LLM 调用也贵，这两点对即时游戏都是硬伤。但如果做成**异步游戏**，它们反而都成了优势：

- **每天一次**：打开游戏，读几封新信，看编年史，做几个决定，大约 5 到 15 分钟。
- **世界在离线时运行**：一天之内，河谷里可能过去一两个季节。
- **LLM 按“天”批量调用**：每天为每个玩家生成一次信件和编年史，而不是每一步都调用，成本可控。

可以参考的节奏有书信游戏、Lifeline 这类实时文字游戏、Animal Crossing 的现实时间，以及放置类游戏。

同时，开局不能让玩家对着一片空地等好几天。可以参考 Dwarf Fortress 的世界生成：玩家到来之前，先预先模拟一段“深历史”，一开局就已经有族群、方言、遗迹和旧故事。

### 2.6 为游戏可以放松的原则

| 原则 | 实验模式 | 游戏模式 |
| --- | --- | --- |
| 世界不写剧本 | 保持 | **保持**。这是这个游戏和普通 AI 故事游戏的根本区别 |
| LLM 不能直接改世界状态 | 保持 | **保持**，否则玩家的理解就失去了意义 |
| 历史不清零 | 保持 | **保持**，单人模式可以考虑提供有限的存档 |
| 中介必须诚实 | 保持 | **放松**：使者可以有偏见，但偏见必须是真实存在、可以被发现的机制，而不是 LLM 的胡编 |
| 世界设定不针对体验调整 | 保持 | **放松**：可以提供“世界预设”和难度，也就是在运行前调整世界设定层 |
| 呈现要朴素 | 保持 | **放松**：名字、肖像、旁白、音乐都可以做得很丰富 |

有一条要特别注意：**使者的偏见必须是设计出来的，不能是 LLM 的幻觉。** 如果信里写的事情在日志里根本不存在，而且玩家查证后发现是模型编的，玩家对整个游戏的信任就会崩塌。所以实验模式里的“真相审计”在游戏里依然需要，只是它现在的作用是维护游戏的完整性。

### 2.7 游戏特有的风险

- **前期无聊**：涌现世界的开头往往很平淡。对策是预先模拟深历史，再加上强有力的策展。
- **居民不够可爱**：小神经网络驱动的小点，很难让人产生感情。对策是在呈现层下功夫：命名、谱系、肖像、使者的讲述。人对有名字、有过去的东西会产生感情。
- **玩家想要直接控制**：间接控制并不适合所有人。要在早期明确告诉玩家，这是一个关于影响而不是控制的游戏。
- **LLM 成本和延迟**：用异步和批量调用解决，并尽量把重复性的工作交给小模型。
- **内容安全**：玩家可能让使者说任何话。使者的输出需要约束和过滤。

## 3. 当游戏框架：哪些东西可以复用

### 3.1 框架提供什么，世界作者提供什么

| 模块 | 框架提供 | 世界作者提供 |
| --- | --- | --- |
| 世界内核 | 格子和实体的存储、守恒和成本结算、居民心智的演化和学习、JAX 后端 | 具体的物理、物种、动作、世界设定 |
| 历史 | 事件日志、快照、分叉、回放、确定性随机数 | 无 |
| 观测层 | 通用检测器：个体和谱系、群体聚类、事件、信号统计、新颖性 | 世界特有的事件定义（比如“修堤”“过河”） |
| 中介运行时 | 编年史记忆、策展、呈现生成、干预规划、预算、真相审计 | 中介的人设和语气 |
| 使者运行时 | 化身和世界的绑定、局部感知、行动付费、汇报协议和带宽限制 | 使者的角色、立场和数量 |
| 窗口 | 编年史、实验室、接触、破译笔记等界面组件 | 美术和风格 |
| 玩家接口 | 意图输入、杠杆、反馈记录 | 这个世界开放哪些杠杆 |

季风河谷只是其中一个“世界包”。换一个世界包，比如深海热泉、孢子星球、蚁群城市，就是另一个游戏，而中介、使者、历史和窗口都可以直接复用。

### 3.2 框架最有价值的部分可能是中介层

有一个值得认真考虑的判断：**框架里最通用、最有价值的，可能不是我们的世界内核，而是中介层本身。**

很多模拟游戏已经有很丰富的涌现，比如 Dwarf Fortress、RimWorld、城市和工厂类游戏，还有各种生态模拟。它们共同的问题是涌现不可读：真正有意思的事情发生了，玩家却没看见。RimWorld 的叙事者和 Dwarf Fortress 的 Legends 模式都是在尝试解决这个问题，但都是为各自的游戏写死的。

所以框架可以设计成两层：

- **中介层可以单独使用**：给任何能输出事件流、能接受有限干预的模拟接上观测、策展、叙事和使者。这一层的价值不依赖于我们自己的世界能不能长出语言。
- **世界内核是可选的**：它是给想要“规则即物质”和从零涌现的游戏准备的完整底座。

这样风险就被分开了：就算我们自己的世界短期内长不出有意思的东西，中介层也有独立的价值。

## 4. 建议：以游戏为主形态，先做游戏，再抽出框架

**理由一：不要在做出一个游戏之前先做引擎。** 这是游戏开发里最常见的教训。没有经过真实游戏验证的抽象，大多是错的。先做一个完整的游戏，第二个世界包出现时，再把共同的部分抽出来，框架的边界才会正确。

**理由二：游戏是对“好不好玩”最直接的检验。** 前面定下的成功标准之一，就是“人会不会自己回来看”。实验模式回答不了这个问题，只有游戏能。

**理由三：实验不会丢。** 实验室窗口保留下来，作为游戏里的一种模式，同时也是开发者用来调世界、查问题的工具。研究问题则变成游戏机制，让玩家亲身感受到。

### 路线

| 里程碑 | 内容 | 要回答的问题 |
| --- | --- | --- |
| M0 原型 | 世界 v0.0 到 v0.2（生存、协作、发声）；单人；每天一批信件和编年史；简单的 2D 地图 | 玩家会不会连续一周每天回来看信？ |
| M1 垂直切片 | 一到两个有性格的使者；有限的神迹；破译笔记；预先模拟的深历史 | 破译和间接影响好不好玩？玩家会不会讲出自己的故事？ |
| M2 抽出框架 | 把季风河谷从引擎里剥离成世界包；做第二个很小的世界包，验证通用性；尝试把中介层接到一个现成的模拟上 | 框架的边界对不对？中介层能不能单独使用？ |
| M3 共享世界 | 多个玩家的使者住在同一片河谷里；世界历史对所有人公开；开放给创作者的世界包工具 | 多人的持久历史会不会产生新的玩法和故事？ |

原来的研究路线（`framework.md` 第 8 节）不作废，它变成了 M0、M1 背后的技术路线：世界的各个阶段仍按那个顺序开放，只是每一步的检验标准多了一条“好不好玩”。

## 5. 需要你决定的

1. **主形态选哪个**：游戏、框架，还是研究？本文建议游戏优先，但这取决于你想要的产出是一个作品、一个工具，还是一组发现。
2. **玩家是谁**：神、外星观察者、远方的学者，还是故意不定义？这会决定整个游戏的语气。
3. **单人还是共享世界**：单人更容易先做出来；共享世界更能体现“历史不清零”，但工程和运营难度高得多。
4. **使者由谁驱动**：全部用大模型，还是大部分用小模型、关键时刻才调用大模型？这直接决定成本。
